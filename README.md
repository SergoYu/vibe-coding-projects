# Вайб-кодинг: три учебных проекта

Проекты выполнены по файлу «Гайд по вайб-кодингу». Всё написано на чистых HTML, CSS и JavaScript: без библиотек, сервера, сборщиков и сети.

| Папка | Проект из гайда | Файлы |
|---|---|---|
| `businessvector-onepage/` | 1. Одностраничный сайт «БизнесВектор» | `index.html`, `styles.css`, `script.js` |
| `businessvector/` | 2. Многостраничный сайт «БизнесВектор» | `index.html`, `services.html`, `cases.html`, `about.html`, `faq.html`, `contacts.html`, `styles.css`, `script.js` |
| `finance-app/` | 3. Финансовый калькулятор организации | `index.html`, `styles.css`, `script.js` |

Папки `assets/` нет: локальных изображений в проектах нет, логотип нарисован средствами CSS.

## Запуск

Откройте нужную папку и дважды щёлкните `index.html`. Интернет не нужен. После правок обновляйте страницу через Ctrl+F5.

## Проект 3. Финансовый калькулятор

### Модель (промпт 10)

- Прибыль = Выручка − Переменные затраты − Постоянные затраты.
- Рентабельность продаж = Прибыль / Выручка × 100% при выручке больше нуля.
- При нулевой выручке вместо процента выводится «Не определяется».
- При отрицательной прибыли выводится статус «Убыток».

Решения, которые стоит знать:

- Деньги внутри считаются в копейках целыми числами, поэтому нет ошибок округления вроде 0,1 + 0,2.
- Пустое поле не считается нулём: калькулятор просит ввести 0 явно.
- Допускаются пробелы между разрядами и запятая или точка перед копейками; не более двух знаков после запятой.
- Верхняя граница одного поля — 1 000 000 000 000 ₽.
- При ошибке ввода старый результат скрывается, чтобы он не расходился с полями.

### Контрольная таблица из гайда

Все пять строк проверены в браузере, результат совпал.

| Выручка | Переменные | Постоянные | Прибыль | Рентабельность |
|---|---|---|---|---|
| 500 000 | 300 000 | 120 000 | 80 000 ₽ | 16,0% |
| 400 000 | 250 000 | 200 000 | −50 000 ₽, «Убыток» | −12,5% |
| 0 | 50 000 | 20 000 | −70 000 ₽, «Убыток» | Не определяется |
| 200 000 | 100 000 | 100 000 | 0 ₽, «Безубыточность» | 0,0% |
| 100 000 | 0 | 0 | 100 000 ₽ | 100,0% |

### План тестирования (промпт 12)

Эти случаи тоже прогнаны в браузере; поведение совпало с ожидаемым.

| Тест | Ввод (выручка / переменные / постоянные) | Ожидаемое поведение |
|---|---|---|
| Обычный расчёт | 500 000 / 300 000 / 120 000 | 80 000 ₽, 16,0%, «Прибыль» |
| Убыток | 400 000 / 250 000 / 200 000 | −50 000 ₽, −12,5%, «Убыток» |
| Нулевая выручка | 0 / 50 000 / 20 000 | −70 000 ₽, «Не определяется», без NaN и Infinity |
| Безубыточность | 200 000 / 100 000 / 100 000 | 0 ₽, 0,0% |
| Нулевые затраты | 100 000 / 0 / 0 | 100 000 ₽, 100,0% |
| Пустые поля | все пустые | Подсказка у каждого поля, результата нет |
| Отрицательное число | −100 / 50 / 20 | «Значение не может быть отрицательным» |
| Буквы | abc / 50 / 20 | «Введите число…» |
| Запись `1e5` | 1e5 / 50 / 20 | Отклоняется как не число |
| Три знака после запятой | 100,555 / 0 / 0 | Просьба указать не более двух знаков |
| Копейки | 1250,50 / 250,25 / 0,25 | 1 000 ₽, 80,0% |
| Очень большое число | 1 000 000 000 001 / 1 / 1 | «Слишком большое число» |
| Кнопка «Сбросить» | после любого расчёта | Поля, ошибки и результат очищены |

### Диаграмма и пояснения (промпт 14)

Под результатом показаны два горизонтальных столбца в одном масштабе: выручка и суммарные затраты. Сделано на CSS, без библиотек. Суммы подписаны рядом, при наведении на строку видна разбивка затрат. Формулы не менялись.

### ИИ-модуль: прогноз по истории месяцев

Второй раздел калькулятора превращает его в ИИ-решение. Пользователь вводит выручку и все затраты за 6–24 месяца, и модель машинного обучения:

1. находит аномальные месяцы — значения, которые сильно выбиваются из тренда (модифицированный z-показатель больше 3,5 и отклонение больше 10%), и исключает их из обучения;
2. обучается на остальных месяцах: линейная регрессия по времени для выручки, затрат и прибыли;
3. прогнозирует 3 месяца вперёд с диапазоном 95%;
4. проверяет своё качество: обучается без последних 3 месяцев и сравнивает прогноз выручки с фактом (MAPE);
5. оценивает риск убытка: «высокий», если прогноз прибыли уходит в минус, «возможен», если в минус уходит только нижняя граница диапазона.

Всё считается в браузере, данные никуда не отправляются. Кнопка «Заполнить примером» загружает демонстрационные данные: 12 месяцев с падающей прибылью и разовым всплеском затрат в мае 2026. На них модель находит аномалию, показывает ошибку 0,7% на проверке и прогнозирует убыток в январе 2027.

Проверено: на точной линейной зависимости прогноз совпадает с ожидаемым, а ошибка равна 0%; на постоянных значениях не появляются NaN; на растущей прибыли риск не выявляется; разовый всплеск находится и не искажает прогноз; ошибки ввода, меньше 6 и больше 24 месяцев обрабатываются.

### Финальный чек-лист (промпт 15)

Проверено по коду и автоматическим прогоном:

- формулы прибыли и рентабельности;
- отказ от отрицательных, нечисловых и пустых значений;
- «Не определяется» при нулевой выручке, отсутствие NaN и Infinity;
- статус «Убыток» и знак минус;
- формат денег с пробелами и процент с одним знаком после запятой;
- отсутствие обращений к сети;
- нет горизонтальной прокрутки на ширине 375 px.

Проверьте в браузере сами:

- открытие двойным щелчком по `index.html`;
- удобство ввода с клавиатуры смартфона;
- понятность пояснений для человека, не знакомого с терминами;
- вид на вашем телефоне после публикации.
